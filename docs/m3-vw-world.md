# M3 — отчёт: `vw.world`

**Дата:** 2026-08-11 · **Ветка:** `modules-migration` · **Статус:** приёмка пройдена

Матрица {MSVC, Clang} × {Debug, Release} зелёная, во всех четырёх конфигурациях
**140/140** тестов, приложения собираются. Плюс пятая конфигурация — headless,
без Vulkan, GLFW и imgui: те же 140 тестов.

## Что стало модулем

`vw.world` — третья модульная библиотека. Восемь интерфейсных партиций, одна
имплементационная и класс `world` в первичном интерфейсном юните:

| Партиция | Содержимое |
|---|---|
| `:model` | `model`, `page_pool`, `model_identity`, `model_identity_pool`, `model_registry` |
| `:anim` | клипы, треки, каналы, ключевые кадры, слои, FSM, реестр клипов |
| `:serial` | vox/voxa — парсеры, писатели, `asset_storage` |
| `:index` | `spatial_layer`, `dynamic_aabb_tree` |
| `:components` | 14 компонентов |
| `:terrain` | `terrain_generator`, `gen_column`, `chunk_loader`, перлин-генератор |
| `:grid` | `chunk`, `world_grid` |
| `:systems` | 11 систем + концепты необязательных хуков |
| `:logging` | **имплементационная** партиция: `log::warn` и соседи для кода мира |
| `vw.world` | класс `world`, `vox_serializer`, `vox_deserializer` |

Геометрия `vw::spatial` (`aabb`, `plane`, `ray`, `frustum`) уехала не сюда, а в
**`vw.core:spatial`**: это чистая математика без состояния мира, и держать её в
`vw.world` значило бы тащить весь мир ради `ray` в редакторе. Взаимные
зависимости (`aabb` ↔ `ray`) не дают разнести четвёрку по разным партициям.

## Ключевые решения

**Класс `world` живёт в первичном интерфейсном юните, а не в партиции.** Партицию
`:world` пришлось бы называть иначе, чем файл первичного юнита, а выигрыша нет:
всё равно любой потребитель импортирует модуль целиком. Партиции, которым нужен
`world` (`:systems`, `:grid`), объявляют его вперёд — внутри одного модуля это
законно и цикла импортов не создаёт.

**Логирование в мире идёт через имплементационную партицию.** `vw/log/logger.h`
остаётся заголовком до M6 (там `<format>` в GMF ссорится с текстовыми
включениями потребителей), но включить его в имплементационный юнит нельзя —
внутри него `import vw.core`, а импорт вне преамбулы модуля запрещён. Решение —
партиция `vw.world:logging` с теми же шаблонами: она **не видна** снаружи
модуля, поэтому `import std` в ней безопасен, а 14 мест вызова `log::warn(...)`
переехали без правок.

**Что осталось инлайном в интерфейсе.** Пер-воксельные и пер-узловые обращения:
`model::get_voxel`/`is_empty`/`get_page*`, `page_pool::get`, все аксессоры
компонентов, `aabb::intersects`, `frustum::intersects`. Всё, что стоит дороже
пары инструкций — конструкторы, `compute_own_boundaries`, обход дерева, разбор
файлов — ушло в `.cpp`. Правило то же, что вывел бенчмарк M2: через границу
модуля инлайнится только то, чьё тело лежит в интерфейсе.

**Псевдонимы `world_type`/`registry_type`/`chunk_type`/`grid_type` удалены.** Они
были нужны шаблонам до M2; теперь это просто лишний уровень имён.

## Headless-сборка

```
cmake -S . -B build/headless -G Ninja -DVW_BUILD_GFX=OFF -DVW_BUILD_APPS=OFF \
      -DVCPKG_MANIFEST_NO_DEFAULT_FEATURES=ON ...
```

- `VW_BUILD_GFX=OFF` — `engine/CMakeLists.txt` собирает core/ecs/world и выходит
  до `find_package(Vulkan|glfw3|imgui)`; таргета `vwengine` в такой сборке нет.
  `VW_BUILD_APPS=ON` вместе с этим — ошибка конфигурации: приложениям нужно окно.
- Зависимости gfx вынесены в vcpkg-фичу `gfx` (включена по умолчанию), поэтому
  headless-джоб ставит только Catch2 — ни Vulkan-Headers, ни GLFW, ни imgui.
- Тесты линкуются на `vw_core`/`vw_ecs`/`vw_world` напрямую, а не на `vwengine`.

Проверка приёмки: `dumpbin /dependents` на `world_tests.exe` из headless-сборки
показывает только CRT и `KERNEL32.dll`; в `build.ninja` нет ни одного упоминания
`vulkan-1.lib`, `glfw3`, `imgui.lib`.

Новый таргет `world_tests` (`tests/world/headless.test.cpp`) — четыре теста,
которые крутят мир без GPU: создание сущности с моделью, обновление границ при
движении, уведомление сетки мира о переехавшем наблюдателе, круговорот вокселей
через реестр моделей. TU импортирует `vw.world` напрямую, без единого заголовка
движка, — это и есть проверка «`import vw.world` не тащит vk::/GLFW».

## Что вскрылось попутно

**Регрессия M2: таблица зависимостей изменений была пуста.** Отчёт M2 утверждал,
что мир заполняет её в конструкторе двумя строками; на деле не заполнял никто.
Последствия: `notify_changed<transform_component>` переставал будить
`spatial_component`, `world_view_component` и `light_component`. То есть границы
сущностей не пересчитывались после движения, свет не следовал за источником, а
сетка мира не подгружала колонки при перемещении камеры. Юнит-тесты этого не
видели. Теперь четыре зависимости регистрируются в `world::world()`, и два теста
из `world_tests` падают, если их убрать, — проверено.

**`flat_terrain_generator` удалён.** Он ссылался на несуществующие
идентификаторы блоков (`grass_1`, `grass_2`, `dirt_2`) — то есть не
компилировался ни разу с тех пор, как поменяли палитру: всё тело жило в
`.inl.h`, который никто не включал. Перенос в модуль это вскрыл сразу.

**Clang снова поймал то, что MSVC простил.** `mesh_pool.h` и
`app_state.h` объявляли вперёд `vw::asset::model` и `vw::ecs::world` — теперь это
сущности модуля, и объявлять их в глобальном модуле нельзя. Заменено на
включение шима.

**`std::ranges::sort` не работает на `keyframe<T>`.** `ranges::less` требует
`totally_ordered`, а у ключевого кадра есть только `<` и `==`. Остался
`std::sort`.

## Метрики сборки

Полная сборка (Release, MSVC, Ninja, с приложениями): **17,9 с** против 24,1 с
после M2 — минус четверть. Тела из `.inl.h`, которые раньше инстанцировал каждый
потребитель, теперь компилируются один раз.

| Правка | Пересобрано TU | Время |
|---|---|---|
| реализация системы (`spatial_system.cpp`) | **1** | 2,3 с |
| интерфейс систем (`systems.cppm`) | 33 | 12,3 с |
| интерфейс моделей (`model.cppm`) | 38 | 15,2 с |

Правка тела системы стоит один TU — до M2 она пересобирала всех потребителей
мира. Правка интерфейса всё ещё задевает 33–38 TU: их держат заголовки `gfx`,
которые текстуально включают шимы. Это уйдёт в M5.

Объём: 2 754 строки интерфейсов партиций, 5 811 строк имплементационных юнитов.
Из дерева `engine/include` удалено 7 531 строка — 58 заголовков стали шимами по
девять строк.

## Приёмка M3

- ✅ `vw_world` линкуется и тестируется без Vulkan, GLFW и imgui — отдельная
  конфигурация зелёная, 140/140.
- ✅ `import vw.world` не тащит vk::/GLFW-символы: headless-бинарь зависит
  только от CRT, зависимости gfx не ставятся вовсе.
- ✅ Sculptor и остальные приложения работают в смешанном режиме (модули
  core/ecs/world + header-only gfx), обе конфигурации, оба компилятора.

Развязка «мир → рендер» через dirty-set из эскиза фазы не понадобилась: мир и так
не знает о мешах, gfx сам опрашивает `changed<model_component>()`. Приоритетная
очередь ремеша остаётся задачей E2.
