# M6. Приложения, тесты, зачистка

Статус: **выполнено**. В репозитории не осталось ни одного `.inl.h` и ни одного
`#include` собственного заголовка; `engine/include` удалён целиком.

Фаза оказалась не «зачисткой», а последним содержательным шагом миграции:
переходный режим держался на одном гвозде, и вынуть его получилось только
вместе с приложениями.

## M6.0 — почему прелюдии нельзя было убрать по частям

Интерфейсные партиции брали стандартную библиотеку через global module fragment,
а шимы дублировали тот же набор заголовков в `module_prelude.h` — иначе MSVC
объявлял одни и те же сущности дважды. D1 разрешал `import std` в
экспортируемых партициях начиная с M6; 27 `.cppm` перешли на него одной правкой.

Дальше выяснилось главное: **как только интерфейс берёт std из модуля,
потребитель теряет право включать std-заголовки текстуально**. Приложение,
которое делает `import vw.gfx` и `#include <unordered_set>`, падает на
`unordered_set: переопределение аргумента по умолчанию`. Зелёного промежуточного
состояния между «движок на `import std`» и «приложения на `import`» не
существует — их пришлось делать одним заходом.

Два побочных следствия:

- `import std` не даёт макросов. `offsetof`, `assert`, `FLT_MAX`, `UINT32_MAX`
  пришлось либо вернуть точечными `<cstddef>`/`<cassert>` в global module
  fragment, либо заменить на `std::numeric_limits`.
- В `log.cppm` global module fragment остался — но не ради заголовков, а ради
  `#ifndef VW_LOG_MIN_LEVEL`: опция сборки приходит макросом и должна
  разрешиться до того, как пурвью назовёт её.

## Логгер собрался в одно место

`vw::log::info` жил в заголовке `vw/log/logger.h` **и** в трёх копиях —
имплементационных партициях `:logging` модулей `vw.world`, `vw.platform` и
`vw.gfx`. Причина была ровно одна: экспортируемая партиция не могла взять
`<format>`, а включить заголовок в модульный юнит нельзя (внутри него `import`,
а импорт вне преамбулы запрещён).

Теперь может. Форматирующий слой переехал в `vw.core:log`, три партиции-дубликата
удалены. Это был самый заметный долг переходного режима: одна и та же дюжина
шаблонов существовала в четырёх экземплярах.

## M6.1 — тесты и мелкие приложения

Пять `main.cpp` и три теста перешли на `import`. Тестовые и прикладные таргеты
получили `vw_use_std_module()`.

**Arena тоже стала модулем.** Вопрос пользователю был только про Sculptor, но у
arena нашлось четыре собственных `.inl.h`, а критерий приёмки говорит про весь
репозиторий. 967 строк, партиций не потребовалось — один `arena.cppm` и пять
имплементационных юнитов. `render_debug_hud` был `inline`-функцией в заголовке
и звал ImGui: разделён на объявление в интерфейсе и тело в `debug_hud.cpp`.

## M6.2 — `vw.sculptor`

119 файлов, 9,7 тысячи строк, 56 пар `.h`/`.inl.h`.

Зависимости оказались циклическими на уровне каталогов: `app` тянет всё, и всё
тянет `app`. Разомкнулось выделением состояния в отдельную партицию — `app_state`
не зависит ни от чего, кроме движка:

```
:state → :operations → {:services, :tools} → :ui → :app
```

Внутри партиции заголовки уложены топологической сортировкой по их же
`#include`-графу, иначе объявления встают в неверном порядке.

Три места, где ImGui протекал в объявления, вычищены, а не спрятаны за
`#include <imgui.h>` в интерфейсе: `to_imvec4` стал файл-локальной функцией
`color_palette_panel.cpp`, `render_time_ruler` принимает `vec2f` вместо
`ImVec2`, а `ui_utils` разделён на объявления и тела. ImGui теперь есть только в
global module fragment имплементационных юнитов.

`sculptor_version.h.in` — единственный оставшийся текстовый заголовок: его
генерирует `configure_file`, и `constexpr`-модулем это не выражается. Заодно из
него убран `#include <string>`: рядом с `import std` он не нужен, а `version_string`
работает и как `const char*`.

## M6.3 — удаление дерева

`engine/include` — 116 файлов — удалён. `vwengine` перестал быть носителем
include-каталога и остался просто набором из пяти модульных библиотек.

## M6.4 — CI и линт

Джобы Ubuntu и macOS удалены: собрать этот проект они не могут в принципе.
`import std` требует модуля стандартной библиотеки, а Clang здесь берёт его из
`std.ixx` от MSVC (`cmake/vw_std_module.cmake` падает без `VCToolsInstallDir`) —
конфигурация вне Windows не проходит вообще. Вместо трёх платформ — матрица
{MSVC, Clang} × {Debug, Release}, headless-джоб без Vulkan SDK и линт.

**CI не проверен:** GitHub Actions локально не запускается, workflow написан по
известным требованиям сборки и может потребовать правок при первом прогоне.

`scripts/lint_modules.py` проверяет шесть инвариантов: нет `.inl.h`; нет
`#include` своих заголовков; C API Vulkan только в `renderer.cpp` (граница
ImGui) и `window.cpp` (граница GLFW); `vk::` только внутри `vw.gfx`; `vk::detail`
только в `vulkan_context.cpp`; никто не реэкспортирует биндинг. Комментарии и
строковые литералы вырезаются перед проверкой — иначе `"VK_LAYER_KHRONOS_validation"`
и комментарий про `vk::SurfaceKHR` дают ложные срабатывания. Сейчас: 0 нарушений.
